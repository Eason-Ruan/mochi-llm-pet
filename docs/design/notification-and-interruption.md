# Mochi 的通知、提醒与打扰层级

本设计适用于桌面端的到点提醒、软提醒、专注建议和阶段结束提示。一次提醒以事项 ID 和发生轮次标识。用户主动推迟会开始新一轮，旧通知上的动作仍绑定原轮次。

## 何时联系用户

| 事件 | 谁作决定 | 用户会看到什么 |
| --- | --- | --- |
| 用户约定「五分钟后提醒我转账」 | 宿主根据原消息时间算出到点时间，由本地调度履约 | 一次可操作的主提示，铃铛菜单同时可以处理。即使处于专注状态也按时投递 |
| 用户约定「开完会再提醒我收衣服」 | System 2 结合用户原话、当前 Observation、允许窗口、最近接触与推迟代价判断 | 会议中可以静默并安排复查。符合条件时可以发一张无声卡。明确约定的最晚时间仍由本地时钟负责 |
| 正在持续工作，可能适合开番茄钟 | System 2 每 60 秒有一次常规思考机会，业务事件也可唤醒。语义判断决定是否值得提议 | 默认可用小猫头顶的无声卡，接受后才开始。工作状态本身可以支持建议。拒绝、已有同类提议、证据不足均可成为静默理由 |
| 阶段结束时碰上提醒到期 | 专注服务先按时结算。桌面端归并同批声音，模型结合已有阶段和用户习惯决定是否还需要建议 | 保留到点提醒的操作入口。已按习惯启动下一阶段时，同一切换无需再提议 |
| 解锁或从休眠恢复 | 宿主核对有效轮次、到期时间及此前投递归属 | 积压事项收进铃铛。挂起期间已过期、完成或推迟的旧轮次不会逐张补弹 |

## System 2 如何表达打扰程度

提醒和提议使用 `presentation.level`，小猫短提示使用 `level`。宿主执行前检查工具授权、目标与轮次、可用渠道、锁屏、声音设置及已提交的投递。旧调用保留兼容映射。

| 字段值 | 体验 | 范例 |
| --- | --- | --- |
| `quiet` 静默 | 本轮没有新增气泡、角标或声音。必要时登记复查 | 会议尚未结束、用户刚拒绝同一建议、信号不足 |
| `passive` 待查看 | 在对应菜单或提议列表保留入口，用户主动打开时可以处理 | 普通待办、可以晚些决定的提议。带硬期限的提醒仍保留兜底 |
| `actionable` 主动可操作 | 使用一个可用主渠道发无声提示 | 普通提醒可直接确认或推迟。番茄钟建议可直接接受或拒绝 |
| `enhanced` 加强 | 结合紧迫理由及用户偏好请求更强提示。声音独立控制 | 用户明确要求加强提示。事项设为「仅无声提示」时仍可准点展示 |

事项的 `reminder_rule.sound` 可省略、设为 `false` 或 `true`。提醒详情页对应「跟随默认设置」「仅无声提示」「允许提示音」。允许提示音仍受全局开关、当前渠道和同批合并约束。推迟保留该选择。只改声音保留当前轮次和展示状态。

用户只说「开完会再提醒」时，可以只保存情境条件。`reminder_rule.timing_context` 保存一段与提醒时机相关的用户原话，最长 280 字符。允许共享文本时，相关候选才会带上原话。关闭共享时，模型只看到存在条件的标记。事项的私人说明不会随候选发送。

## 主渠道与操作

- 桌面默认优先使用可操作的小猫卡。已预登记的系统通知继续承担离线兜底。macOS 在实际投递时把前台决定交给 Mochi，桌面可用且能安全接手时才转交给小猫。Mochi 在后台时，系统可以直接展示横幅，即使小猫浮在其他应用之上。
- 新的 macOS 提醒支持「确认收到」和适用时的「稍后 5 分钟」。点击通知正文打开对应事项。原生按钮与菜单检查相同的有效轮次。确认收到仅回执本轮，事项完成由独立操作决定。旧通知和能力受限的平台保留兼容入口。
- 系统已取得投递归属时，具备原生操作的通知不会再自动配一张小猫确认卡。平台交付结果未知时保留原归属。铃铛中的待处理入口持续可用。未处理、收起、拒绝、收到及推迟分别记录，单凭无人回应不足以升级。
- 多个提醒竞争同一显示位置时，主卡与菜单配合。用户在菜单仍可逐个处理。声音按同一批次归并，分别尊重提醒音和阶段音开关。

## 可观测性与平台边界

System 2 接收最近一小时最多八次接触，按事项轮次归并。记录主渠道、可回看的入口、各表面的展示证据、声音请求和用户回应。Qt 绘制、系统报告送达、系统受理但展示未知、用户点击各有独立含义。发出声音请求无法证明用户听见。记录中不包含提醒标题和屏幕原文。[接触记录](../../deskpet/system2/contact_history.py) · [桌面渠道仲裁](../../deskpet/c_ui/presentation.py) · [原生通知适配](../../deskpet/c_ui/native_notifications.py)

macOS 预登记的兜底横幅采用无声策略。不同事项同时到期时各自保留原生操作，使用同一通知分组。Mochi 在后台时，系统仍可逐条展示。显式设了失效时间的事项使用运行中的本地调度，以免系统在过期后仍展示陈旧提醒。

软提醒提前转交小猫前会验证原预约已撤回。正常退出会尝试恢复兜底，重启会复核在途记录。如果进程在预约撤回后、实际展示或重新登记前异常退出，提醒可能会错过最晚时间。

## 验收

可重复的影子回放覆盖六类场景：固定时间转账、会议与弹性家务提醒、工作中建议番茄钟、阶段结束与事项同时到期、锁屏后恢复、已推迟后点击旧系统按钮。用逻辑时钟、临时数据和模拟通知适配器计算准点履约、同轮重复主动展示、同批重复声音、首次主提示可操作及失效或推迟后的陈旧提示。Qt 与 macOS 回调契约另行测试。回放衡量宿主能否落实给定模型动作，线上模型在真实用户场景中的判断准确率需要另行测量。[回放场景与校验](../../tests/test_system2_semantic_replay.py) · [桌面集成测试](../../tests/m0/test_interruption_flow.py)
